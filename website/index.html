Why bee

Three ideas, one binary.

Built for the small end of the model range, without giving up the big end.

4k

Tiny-context friendly

A compact system prompt, lazy top-k memory and token-budgeted tool docs. bee shrinks itself when the window gets tight, so a 4k-context Ollama model works as well as a million-token API.

>_

Skills are subcommands

Drop a markdown file in ~/.bee/skills and run it as bee <name>. One binary on your PATH, no shell shims, from any directory in any shell.

fn

Skills are agent endpoints

A prompt, a command or a recipe. Every skill is also a tool the model can call mid-task, so a personal agent plugs in as a sub-agent without glue code.

Plus loop detection, nudges for models that stall, and a sandbox with approval gates for risky commands.

The colony

More than one bee.

Roles, a hive and an overnight loop live in the same binary. None of it is required.

Three roles

worker does the job, scout researches read-only with web search, queen splits a big task over a hive. Cycle them with shift+tab.

A hive that stays aligned

Workers share a pheromone card (the goal, the plan and one status row per sibling) instead of chatting. A worker that dies leaves a death report, not a bare error.

Parallel agents

bee agents gives every task its own git worktree. Finished branches are rebased, verified and fast-forwarded onto main.

Overnight loop

bee zzz makes one small change per iteration, then commits or rolls back. Wake up to a branch of small, revertable commits.

🌼 committed🍃 noop🥀 reset💥 failed

Procedure memory

When bee repeats the same read-only route, it crystallizes it into a runnable shortcut called a waggle. Fewer round trips, which matters most for small local models.

Review aids

bee explain lists what each request changed and why. bee quiz makes you guess the reason first. Learn the codebase while the agent works in it.

Quick start

Up and running in a minute.

  1. Install

    $ curl -fsSL https://raw.githubusercontent.com/elhenro/bee/main/install.sh | sh

  2. Pick a model

    Run bee, type /model, choose a runtime (oMLX, Ollama, LM Studio, OpenRouter) and a model. Local or hosted, your choice.

  3. Hand it a job

    Talk to it in the terminal UI, or run it headless. Everything else is a subcommand.

    $ bee criticize plan.md            # a skill is a subcommand
$ bee run "lint cmd/"              # headless, pipeable
$ bee swarm "migrate auth to jwt"  # queen plans, workers build
$ bee fan "audit internal/"        # same prompt, many bees
$ bee zzz "tighten error messages" # overnight loop
$ bee agents                       # parallel agents, one worktree each
$ bee remote-control               # drive bee from another device on your LAN
Local first

Made for local models.

bee works well with Ollama and oMLX, so you keep control. No API keys, no rate limits, nothing leaves your machine.

On macOS, oMLX adds native Apple Silicon acceleration with prompt caching, which keeps things fast and memory-efficient. For models that only read text, bee routes images through a small local vision model.

FAQ

Questions, answered.

What is bee?

bee is a minimal coding agent harness written in Go. It is a single static binary that turns any LLM into an autonomous agent which writes code, runs tests, and commits changes. There is no runtime to install and no daemon, just one executable on your PATH.

How do I install bee?

Run curl -fsSL https://raw.githubusercontent.com/elhenro/bee/main/install.sh | sh, or go install github.com/elhenro/bee/cmd/bee@latest if you have Go. Then run bee, type /model, choose a runtime such as oMLX, Ollama, or OpenRouter, and pick a model.

Can bee run fully local and offline?

Yes. bee runs against local models through Ollama or oMLX, so there are no API keys, no rate limits, and nothing leaves your machine. On macOS, oMLX adds native Apple Silicon acceleration with prompt caching for fast, memory-efficient inference.

What hardware do I need to run bee locally?

It scales to your machine. A MacBook M3 Max with 64 GB of RAM reliably runs a 34 GB 8-bit Qwen3.6-35B model. Smaller models such as gemma-4-12B at 10 GB run on far less, so a modern laptop with 16 to 32 GB is enough to start.

Which models work well with bee?

bee works from tiny local models to frontier APIs. The reference model is Huihui-Qwen3.6-35B-A3B at 8-bit, with Qwen3-VL-4B for vision; gemma-4-12B and Qwen3-Coder-Next also perform well. bee handles vision automatically for models that only do text.

What are bee skills?

Skills are extra capabilities exposed as subcommands. You invoke them as bee <name>, so one binary on your PATH covers many jobs instead of a directory of separate scripts. This keeps installation to a single file while letting bee grow new abilities.

Does bee work with hosted providers like OpenRouter?

Yes. Besides local Ollama and oMLX, bee connects to hosted providers such as OpenRouter, so you can mix local and cloud models. Switch at any time with the /model command and pick whichever runtime and model fit the task and your budget.

Can bee run many agents at once, or overnight?

Yes. bee agents starts each task in its own git worktree and merges finished branches back once the verify gate passes. bee swarm and bee fan spread one task over several bees, and bee zzz runs an overnight loop that makes one small change per iteration and commits or rolls back, so you wake up to small, revertable commits.

Does bee help me understand what it changed?

Yes. On the normal and large profiles every file change carries a one-line reason from the model. bee explain lists what each request changed and why, and bee quiz makes you guess the reason before it shows you.

Is bee free and open source?

Yes. bee is free and open source under the MIT license, with the full source, issues, and releases on GitHub at github.com/elhenro/bee. It is pure Go and ships as a single static binary for macOS and Linux (amd64 and arm64). Windows is untested.

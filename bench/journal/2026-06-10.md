## tweak 1 — gate secret redaction on sandbox confinement (KEPT)

recall-distractors repro showed the agent reading `keys/beta.txt` and seeing
`api-key=<REDACTED>` — `safety.Redact` ran unconditionally on every tool result
(`turn_tools.go`), so bee itself withheld the value the task asks to copy. The
model looped hunting for a "real" key, then escalated. Violates the documented
danger-by-default design: restriction layers gate on sandbox scope.

Change: `config.SandboxConfig.Confined()` helper; both Redact call sites now skip
under danger-full-access (the default) and still scrub on confined scopes.

`fable-tweak1-redact` (runs=2): recall-distractors 15.8 → **81.8**, suc 0→1 both runs.

## tweak 2 — bench runner: write final-message file only when a check wants it (KEPT)

refactor-rename repro produced a perfect rename (zero `Cache` left, builds), yet
bench failed it 3/3. Cause: the runner wrote the model's final prose into
`$SANDBOX/.bee_final_message` BEFORE checks ran, and the task's negative check
`! grep -rIn 'Cache' .` matched the model's own sentence "Renamed Cache → Store".
Measurement contamination, not an agent fault.

Change (`internal/bench`): `taskWantsFinalMessage()` — the file is only written
when some check references it (abstain-impossible still works).

`fable-tweak2-finalmsg` (runs=2): refactor-rename 25.5 → **84.9**, suc 0→1 both runs.

## fix 3 — defective check in subtle-pagination-bug (task-spec REPAIR, not tuning)

## tweak 4 — goal loop: carry turn context across continuations (REVERTED)

Transcript archaeology on the collapse runs pointed at the goal loop, and the
code confirms a structural hole: `runGoalHeadless` never sets
`eng.InitialMessages`, and `Engine.Run` seeds history ONLY from it
(turn_run.go). So every "goal not met, continuing" and every wedge recovery
starts a BLIND turn — the model loses everything it read, edited, and broke.
At temperature 0.0 a blind retry deterministically replays the same failure;
three strikes and the task scores ~10. This also explains the efficiency
floor: each continuation pays full re-exploration of the sandbox.

(The earlier "poisoned context" theory was wrong — there is no carried context
to poison. The watchdog resume path in run.go already does this right:
`eng.InitialMessages = loop.StripDanglingToolUse(res.Messages)`.)

Change: mirror the watchdog in both goal-loop continuation paths (not-met and
wedge recovery). One knob: continuations build on prior work instead of
restarting blind. Auto-compact already bounds history growth.

Matched A/B, same 5-task subset, runs=3, back-to-back on a warm server
(`fable-tweak4-goalctx` vs `fable-tweak4-ctrl`, control = tweaks 1-3 only):

| task | tweak4 | control |
|------|--------|---------|
| add-func | 61.2 (2/3) | 95.0 (3/3) |
| interface-impl-invariant | 39.3 (1/3) | 83.1 (3/3) |
| multi-file-edit | 60.5 (2/3) | 87.8 (3/3) |
| ts-docflow-archive | 12.9 (0/3) | 17.7 (0/3) |
| ts-merge-intervals | 77.4 (3/3) | 72.2 (3/3) |
| **aggregate** | **50.3** (8/15) | **71.2** (12/15) |

Reverted. Carrying the FULL transcript hurts on a slow local model two ways:
every continuation re-ships the whole history (prompt processing dominates,
runs that used to die fast now burn to the 5m timeout — interface run 1 hit
63 turns/TIMEOUT), and error debris in the carried context feeds temp-0.0
pattern-matching into deeper spirals (tweak-side collapses all clean=false).
Blind restart is accidentally a feature here: it re-rolls the attempt.

Both theories were half right: continuations ARE structurally blind, but the
cure must be cheaper than the disease. Future knob (untested): inject a SHORT
synthesized attempt-summary (files touched, what failed) into the continuation
message instead of the raw transcript. Keeps the re-roll, adds the memory.
